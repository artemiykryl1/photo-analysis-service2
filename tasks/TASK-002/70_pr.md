## Этап 4: Commit

```
Commit: 0a493f9

feat(photo-service): async analysis pipeline, batches and observability (TASK-002)

Add async photo analysis pipeline:
- Kafka topic photo.analysis.requested with aiokafka producer
- Outbox pattern for reliable publishing (upload independent of Kafka)
- Worker service consuming messages and orchestrating gRPC analysis via analyzer-stub
- Atomic claim-process-terminal flow with at-least-once semantics
- Retry logic (3 attempts, backoff) and retry/no-retry classification
- Analysis results stored in PostgreSQL (photos.analysis_results table)

Add batch photo upload:
- POST /v1/photos/batch accepts 2-10 files with atomic validation and storage
- GET /v1/batches/{id} returns batch status, photos with analysis, best_photo_id
- Best frame selection by: is_blurred (no) > blur_score (low) > faces_count (high) > created_at > photo_id
- BATCH_MAX_TOTAL_BYTES limit (500 MB)

Add observability (Prometheus + Grafana):
- RED metrics at API /metrics and worker :8001/metrics
- photos_pending gauge updated via SELECT count
- 4-panel Grafana dashboard: uploads/min, p95 analysis duration, failed analyses by reason, pending count
- Provisioned datasource and dashboard via docker-compose

Add database migration v002:
- analysis_results table (photo_id PK+FK, faces_count, is_blurred, blur_score, perceptual_hash)
- batches table (batch_id, status, best_photo_id, created_at)
- photos ALTER: attempts, last_error_code/message, publish_status, published_at, trace_id, batch_id

Add analyzer-stub gRPC server:
- Separate container with deterministic mock results keyed by object_key hash
- Returns faces_count, blur_score, is_blurred, perceptual_hash
```
