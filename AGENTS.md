# AGENTS.md

Этот репозиторий разрабатывается мультиагентным SDD-процессом (Spec-Driven Development).
Главная сессия — **оркестратор**: она не пишет код и не проектирует сама, а ведёт процесс
(Constitution → Specify → Plan → Tasks → Implement) и делегирует специализированным субагентам.

Полная конфигурация оркестратора, правила гейтов и конвейера одной таски — в [CLAUDE.md](./CLAUDE.md).
Определения субагентов (промпты, инструменты, модели) — в [.claude/agents/](./.claude/agents/).

@CLAUDE.md

## Субагенты

| Агент | Роль | Модель |
|---|---|---|
| `context-collector` | Сбор контекста по коду | haiku |
| `architect` | Проектирование (план для кодера) | opus |
| `coder` | Написание кода по плану | sonnet |
| `reviewer-1` | Глубокое ревью (корректность/архитектура) | opus |
| `reviewer-2` | Независимое ревью (безопасность/конвенции) | haiku |
| `test-writer` | Написание тестов | sonnet |
| `test-debugger` | Поиск причины падений и фикс | sonnet |
| `pr-publisher` | Подготовка и публикация PR | haiku |
| `documenter` | Документация и диаграммы | sonnet |

**Диверсификация моделей (правило из ТЗ):** `reviewer-1` (opus) ≠ `coder` (sonnet);
`reviewer-2` (haiku) ≠ `coder` и ≠ `reviewer-1` — два независимых ревью разными моделями.

## Конвейер одной таски (TASK-XXX)

Агенты идут строго по порядку, каждому передаются пути к артефактам (контекст не наследуется):

1. `context-collector` → `tasks/<ID>/10_context.md`
2. `architect` → `tasks/<ID>/20_design.md`
3. `coder` → код + `tasks/<ID>/30_impl.md`
4. `reviewer-1` ∥ `reviewer-2` → `40_review-1.md`, `41_review-2.md` (параллельно)
5. `test-writer` (после двух APPROVE) → тесты + `tasks/<ID>/50_tests.md`
6. `test-debugger` (только при падении тестов) → `tasks/<ID>/60_debug.md`
7. `pr-publisher` (после зелёных тестов и разрешения пользователя) → `tasks/<ID>/70_pr.md`
8. `documenter` (после аппрува) → `tasks/<ID>/80_docs.md` + диаграммы

## Гейты

Дальше тестов/PR не идём, пока **оба** ревью не дали `APPROVE`.
`pr-publisher` вызывается только при зелёных тестах **и** явном разрешении пользователя.
Любое необратимое/внешнее действие (git push, создание PR) — с разрешения пользователя.
Журнал оркестрации по каждой таске — в `tasks/<ID>/00_orchestration.md`.
