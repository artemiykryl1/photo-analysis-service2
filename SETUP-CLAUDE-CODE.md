# Пошаговая настройка мультиагента в Claude Code Desktop

Инструкция, как развернуть конвейер из 10 агентов через механизм **subagents** Claude Code. Проверено на формате Claude Code v2.1.x (июнь 2026).

---

## Как это устроено (важно понять до старта)

В Claude Code **главная сессия — это и есть оркестратор**. Субагент не может надёжно вызывать другого субагента, поэтому маршрутизацию ведёт главная сессия, а её правила лежат в `CLAUDE.md`. Остальные 9 ролей — это файлы‑субагенты в `.claude/agents/`.

Три факта про субагентов, которые определяют дизайн:
1. **Изолированный контекст.** Каждый субагент работает в своём чистом окне и НЕ видит ваш диалог с главной сессией. Единственный канал — текст задания, которое ему передаёт оркестратор. Поэтому в задании всегда указываем пути к артефактам.
2. **Тело файла = системный промпт.** Субагент получает только его + рабочую директорию, без полного системного промпта Claude Code.
3. **Артефакты на диске — это «общая память».** Субагенты читают `.md` из `tasks/<ID>/` через инструмент Read. Это делает SDD‑конвейер естественным: каждый агент пишет свой `.md`, следующий его читает.

Поля во frontmatter:
- `name` — имя для вызова (`Используй агента architect...`).
- `description` — по нему оркестратор решает, когда делегировать. Пишем конкретно и по‑делу.
- `tools` — список инструментов (рычаг безопасности: ревьюверы почти без записи).
- `model` — `opus` / `sonnet` / `haiku` / `inherit` (рычаг стоимости). Алиасы резолвятся в текущие версии: opus→Opus 4.8, sonnet→Sonnet 4.6, haiku→Haiku 4.5.

## Шаг 0. Предварительные требования

1. Установлен **Claude Code** (Desktop или CLI), версия 2.1+.
   - Проверка: запустите `claude --version`.
   - Документация по установке: https://docs.claude.com/en/docs/claude-code/overview
2. Активная подписка/доступ к API с моделями Opus, Sonnet, Haiku.
3. Git‑репозиторий проекта (для PR‑публикатора).
4. (Опционально) MCP‑серверы: git‑провайдер для `pr-publisher`, draw.io/ВК для `documenter`.

## Шаг 1. Разверните структуру файлов

Скопируйте содержимое архива в корень вашего репозитория. Должно получиться так:

```
photo-analysis-service/           ← корень репозитория
├── CLAUDE.md                     ← правила оркестратора (главная сессия)
├── .claude/
│   └── agents/
│       ├── context-collector.md
│       ├── architect.md
│       ├── coder.md
│       ├── reviewer-1.md
│       ├── reviewer-2.md
│       ├── test-writer.md
│       ├── test-debugger.md
│       ├── pr-publisher.md
│       └── documenter.md
├── specs/
│   ├── constitution.md           ← общие правила проекта
│   └── feature-upload/
│       ├── spec.md               ← спека первой фичи
│       └── tasks.md              ← реестр задач
└── tasks/
    └── TASK-001/
        └── diagrams/
```

Команды (из корня репозитория):
```bash
# распакуйте архив сюда, либо создайте вручную:
mkdir -p .claude/agents specs/feature-upload tasks/TASK-001/diagrams
# затем положите файлы из архива на свои места
```

> `.claude/agents/` — это **проектные** субагенты (живут в репозитории, шарятся с командой через git). Если хотите, чтобы агенты были доступны во всех ваших проектах — положите их в `~/.claude/agents/` (пользовательский scope). При конфликте имён проектные перекрывают пользовательских.

## Шаг 2. Закоммитьте в git

```bash
git add CLAUDE.md .claude/ specs/
git commit -m "chore: настройка мультиагента (SDD, 10 агентов)"
```

Так вся команда получит одинаковую конфигурацию агентов.

---

## Шаг 3. Запустите Claude Code и проверьте, что агенты загрузились

В корне репозитория:
```bash
claude
```

Внутри сессии откройте менеджер агентов:
```
/agents
```

Во вкладке **Library** вы должны увидеть все 9 субагентов (context-collector, architect, coder, reviewer-1, reviewer-2, test-writer, test-debugger, pr-publisher, documenter) в разделе Project.

> Важно: субагенты из файлов на диске загружаются **в начале сессии**. Если вы редактируете `.md` агента на диске, перезапустите сессию (`/exit`, потом `claude`), чтобы изменения подхватились. Агенты, созданные/изменённые через `/agents`, применяются сразу без перезапуска.

Проверка одного агента:
```
Используй агента context-collector, чтобы собрать контекст по структуре репозитория. Результат покажи кратко.
```

## Шаг 4. (Опционально) Подключите MCP‑серверы

Нужно только для `pr-publisher` (git) и `documenter` (диаграммы/ВК Доска).

```bash
# пример: добавить MCP-сервер
claude mcp add <имя> <команда-запуска-сервера>
# посмотреть подключённые
claude mcp list
```

Инструменты MCP‑сервера появятся как доступные; при необходимости добавьте их имена в поле `tools` соответствующего агента. Подробности: https://docs.claude.com/en/docs/claude-code (раздел MCP).

> Если MCP не подключён: `documenter` подготовит описание диаграмм в mermaid и сообщит, что для публикации нужен MCP. `pr-publisher` сможет работать через обычный git по Bash.

---

## Шаг 5. Настройте права (permissions)

Гейт «внешние действия — только с разрешения пользователя» опирается на встроенные подтверждения Claude Code. **Не отключайте** их для этого workflow:
- НЕ запускайте с `--dangerously-skip-permissions`.
- Claude Code сам спросит подтверждение на `git push`, создание PR, запись через MCP — это и есть ваш гейт.

При желании можно явно ограничить, что разрешено без спроса, в настройках проекта (`.claude/settings.json`) — но безопасный дефолт уже подходит.

## Шаг 6. Прогоните первую таску (TASK-001)

Откройте сессию в корне репозитория (`claude`) и дайте оркестратору задачу. Главная сессия прочитает `CLAUDE.md` и поведёт конвейер.

### 6.1 Запуск конвейера

```
Возьми TASK-001 из specs/feature-upload/tasks.md (загрузка фото в MinIO + публикация в Kafka,
эндпоинт POST /api/v1/photos). Спека: specs/feature-upload/spec.md.
Веди её по SDD‑конвейеру согласно CLAUDE.md, делегируя субагентам по очереди.
Перед каждым шагом коротко сообщай, кого вызываешь и зачем.
```

Оркестратор должен:
1. Прочитать `specs/constitution.md` и `spec.md`.
2. Создать `tasks/TASK-001/00_orchestration.md`.
3. Вызвать `context-collector` → дождаться `10_context.md`.
4. Вызвать `architect` → `20_design.md`.
5. Вызвать `coder` → код + `30_impl.md`.
6. Запустить `reviewer-1` и `reviewer-2` (можно параллельно) → `40_review-1.md`, `41_review-2.md`.
7. Проверить, что оба `status: APPROVE`. Если нет — вернуть `coder`.
8. Вызвать `test-writer` → тесты + `50_tests.md`. При падении — `test-debugger`.
9. Спросить у вас разрешение, затем `pr-publisher`.
10. Вызвать `documenter`.

### 6.2 Параллельные ревью (опционально, быстрее)

```
Запусти reviewer-1 и reviewer-2 параллельно по tasks/TASK-001/30_impl.md.
```

### 6.3 Точка подтверждения (PR)

Когда дойдёт до публикации, оркестратор остановится и покажет тело PR. Только после вашего «да» `pr-publisher` сделает git‑операции (Claude Code дополнительно запросит подтверждение на сам push).

---

## Шаг 7. Проверьте артефакты

После прогона в `tasks/TASK-001/` должны лежать:
```
00_orchestration.md   ← журнал оркестратора
10_context.md         ← контекст
20_design.md          ← дизайн
30_impl.md            ← что реализовано
40_review-1.md        ← ревью 1 (status: APPROVE)
41_review-2.md        ← ревью 2 (status: APPROVE)
50_tests.md           ← тесты (coverage, прогон)
60_debug.md           ← только если были падения
70_pr.md              ← тело PR + ссылка
80_docs.md            ← документация + диаграммы
diagrams/             ← исходники диаграмм
```

Эти файлы — история разработки таски и доказательство прохождения гейтов. Коммитьте их вместе с кодом.

## Полезные команды и приёмы

### Принудительный вызов конкретного агента
Упомяните его по имени: `Используй агента reviewer-1 для tasks/TASK-001/30_impl.md`. Это обходит авто‑маршрутизацию.

### Управление агентами
- `/agents` — менеджер (создать/изменить/удалить, посмотреть активных).
- Вкладка **Running** — живые и недавно завершённые субагенты (можно открыть/остановить).

### Запуск всей сессии как одного агента
```bash
claude --agent architect
```
Полезно, если хотите поработать только в одной роли.

### Новая таска
Создайте `tasks/TASK-002/`, добавьте задачу в `tasks.md` и повторите Шаг 6 с TASK-002.

### Если агент «не туда» маршрутизируется
Чаще всего дело в `description`. Сделайте его конкретнее (какие задачи, файлы, технологии, условие запуска). Двух агентов с похожими описаниями оркестратор может путать — разводите границы.

## Частые вопросы

**Где orchestrator.py из прошлого варианта?**
В Claude Code он не нужен — оркестрацию ведёт главная сессия по `CLAUDE.md`. Скрипт нужен только при работе напрямую через Agent SDK (программный подход), не в Desktop‑приложении.

**Почему у ревьюверов есть Write?**
Им нужно записать свой `.md`‑артефакт. Промпт строго запрещает им менять исходный код — только писать ревью в `tasks/<ID>/`. Если хотите жёсткую гарантию read‑only по коду, можно убрать у них Write и поручить запись ревью оркестратору (он перенесёт финальное сообщение агента в файл) — но это лишний шаг.

**Можно ли поменять модели?**
Да, поле `model` в каждом файле. Но соблюдайте правило из ТЗ: `reviewer-1` ≠ `coder`, `reviewer-2` ≠ `coder` и ≠ `reviewer-1`. Сейчас: coder=sonnet, reviewer-1=opus, reviewer-2=haiku.

**Субагенты правда работают параллельно?**
Да, главная сессия может запустить несколько одновременно — удобно для двух ревьюверов. Это ускоряет, но расходует больше токенов (у каждого своё окно).

**Изменил промпт агента — не применяется.**
Файлы на диске грузятся в начале сессии. Перезапустите (`/exit` → `claude`) или редактируйте через `/agents` (применяется сразу).
